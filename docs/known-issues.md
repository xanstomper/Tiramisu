# Tiramisu — known issues

Tracked limitations. Every entry here is a *measured* or *honestly unmeasured* fact,
not a guess. Rows are removed only when verified fixed on-device or in the gate.

## Console (on-device)

- **Xbox One / One S / One X: untested on hardware.** The profile path is now
  offline-gated (`tests/test_console_profile`, 69 checks): family table, 5120 MB Dev
  Mode budget, 32 MB ESRAM ledger on One/One S, and a per-family D3D11 level list that
  never asks a GCN 1.1 part for 11_1. None of that is on-device proof. Xbox One S/X are
  x86‑64, so
  PE32 and PE32+ guests are both in the PE space, and Dev Mode + Device Portal
  should install Tiramisu. Expected practical limits: One S is ~1.3 TFLOPS / 8 GB
  DDR3 and One X ~6 TFLOPS / 12 GB GDDR5; neither matches Series X|S headroom, so
  do not expect the Series‑S playables (RACCOIN, Celeste, God of War) or 60 FPS
  targets to reproduce. D3D12/Vulkan/Compute features and CPU‑bound titles are the
  first to fail. Treat the next step as an experiment until on-console proof exists.
  Full hardware/API mapping and the acceptance matrix:
  [docs/xbox-one-family.md](xbox-one-family.md).
- **Celeste v1.4.0.0 — audio silent.** FSB5 Vorbis decode is disabled on console after
  it heap-corrupted on a Series S. Gate defaults off (`fsb_decode = false`); per-game
  override via `tiramisu.profile.ini` (`fsb_decode=1`) is available for testing but
  unproven on-device. See `src/trt/bridge_fmod_studio.cpp`.
- **Factorio — untested on console.** Named target for 60 UPS + audio; not yet run.
  No `proof.json` exists for it.
- **No per-run `proof.json` for legacy titles.** RACCOIN / Celeste / God of War
  evidence is flat legacy artifacts (`docs/proof/*.png/mp4/webp`), not the new
  structured `docs/proof/<name>/proof.json` format.

## Desktop applications

- **Painting works; it is not a compositor.** Every DC now owns a real 32-bit
  raster surface (`src/trt/gdi_raster.cpp`) with an embedded 8x16 DejaVu-derived
  coverage font (`gdi_font8x16.h`, generated by `tools/gen_bitmap_font.py`):
  TextOut/ExtTextOut/DrawText, PatBlt, BitBlt, StretchBlt, SetDIBitsToDevice,
  StretchDIBits, Rectangle/Ellipse/Polygon/Polyline/LineTo, FillRect/FrameRect/
  InvertRect, SetPixel/GetPixel and clip rectangles all draw. Windows get the
  real paint cycle (WM_MOVE/SIZE/NCPAINT/ERASEBKGND/PAINT after show), one
  stable DC per window, and SaveDC/RestoreDC. Verified end-to-end by
  `tests/test_desktop_paint.cpp` (guest PE → WM_PAINT → pixels).
  Pixels are observed through BMP dumps (`TIRAMISU_GDI_DUMP=<dir>`); the console
  host still composites D3D, not GDI, so there is no on-screen GDI window yet.
- **Glyph coverage stops at Latin-1.** ASCII 32..126 plus Latin-1 160..255
  render (191 glyphs); U+0100 and above draw a hollow box (visible, never
  silent). The font is a bitmap scaled to the requested cell, so small sizes
  are legible but not hinted, and there is no anti-aliasing.
- **GDI paths, RoundRect, arcs, regions and transforms:** GDI paths record and
  replay (FillPath/StrokePath/SelectClipPath with a per-pixel clip mask),
  RoundRect corners are real ellipses, Arc/Pie/Chord rasterize, and the GDI+
  world transform is a full affine matrix. Still named: `WidenPath`,
  `SelectClipPath` modes other than RGN_AND/RGN_COPY, `PathToRegion` returning
  the bounding box, rotated bitmaps drawn as their transformed box, and glyph
  scaling under a transform (placement only).
- **Common dialogs do not open, but their text is now logged.** comdlg32 answers
  user-cancel (`FALSE` with the atom logged as `#id`) and DialogBoxParam* returns -1
  by name: there is no dialog host. `DialogBoxParamW`/`DialogBoxIndirectParamW` now
  parse the guest's DLGTEMPLATE (caption, size, style, every item id + text) and
  `MessageBoxIndirectW/A` read their `MSGBOXPARAMSW/A` text, so an engine's own fatal
  message ("Failed to initialize Direct3D") is in the log instead of discarded.
- **Printing is a named stub** (winspool.drv), and uxtheme/DWM answers classic-mode
  values (no theming, composition assumed on).

## Engine synthesizer

- **Launch preflight exists and names blockers.** `trt_engine_launch_preflight`
  (`src/trt/engine_synthesizer.cpp`) resolves the provisioned profile against real
  host capability before the first import binds: unreadable/ARM64 exe, missing engine
  payload, managed image without a Mono host, chosen API with no host device
  (`DXGI_ERROR_UNSUPPORTED`), D3D12 recorded-only, OpenGL traps, no compositor,
  anti-cheat, and graphics/audio imports that only bind to stubs. Verdict lines are
  logged (`trt: [PREFLIGHT] …`) and written into `.tiramisu/profile.json` under
  `"preflight"`. Covered by `tests/test_engine_synthesizer.cpp` stage 15, and
  measured on real titles by the corpus boot (`test_corpus_run --exe` prints a
  `PREFLIGHT <exe>` block before each boot): Cuphead and RACCOIN report only
  `no_gfx_device` + `no_compositor` in the headless harness; `gonext` reports
  `payload_missing` for `Go Next demo_Data`; openttd reports `gfx_not_executed`
  (OpenGL traps) + `no_compositor`. Only graphics/audio/middleware stubs are
  named — a game's own DLL (unityplayer.dll) is never called a stub.
- **Payload closure is checked, and an exe without its engine data is named.**
  Unity needs `<stem>_Data` plus `Managed`/`Mono` (Mono) or `il2cpp_data` +
  `GameAssembly.dll` (IL2CPP); UE needs a `.pak/.utoc/.ucas` or `Content`; XNA needs
  `Content`/`.xnb`. A missing piece is `payload_complete: false` +
  `missing_payload[]` in profile.json and a `payload_missing` preflight blocker.
  Measured on the corpus: Cuphead and RACCOIN close; `gonext` (Unity exe + DLLs with
  no `*_Data`) is now named instead of dying in "Failed to load mono".
- **A non-PE exe is refused, not assumed PE64.** The candidate list is walked in
  score order until one scans as a PE (so a launcher at #1 no longer hides the real
  binary), and `synthesizer: REFUSED <game> - not a readable PE (…); architecture is
  never guessed` is logged when none does.
- **Screen synthesis: 1280x720 windowed by default.** Unity gets
  `-screen-width/-screen-height/-screen-fullscreen 0`, Unreal gets
  `-windowed -ResX=1280 -ResY=720`, and Unreal also gets a synthesized
  `GameUserSettings.ini` under `<title>\Saved\Config\Windows[NoEditor]` (written
  into the guest's C: drive) so a shipped 4K/high-VRAM default does not spend the
  5 GB Dev-Mode budget on buffers the compositor cannot show. `TRT_SCREEN=WxH`
  overrides the size; profile.json records `"screen"`. Covered by
  `tests/test_engine_synthesizer.cpp` stage 16. Not yet synthesized: Unity
  PlayerPrefs (registry) screen keys, and engine .ini files other than Unreal's.
- **`TRT_SYNTH_DRY_RUN=1` classifies and preflights without writing.** The
  corpus boot harness sets it so running the synthesizer over `corpus-local/`
  never drops `steam_appid.txt`/`.tiramisu/` into a title's folder.
- **`steam_appid` 480 is recorded as synthesized.** profile.json carries
  `steam_appid_synthesized` (a preflight note) so a Spacewar sandbox appid is never
  mistaken for the title's real AppID.
- **Disc-image mounting: discovery now covers `.cue` and subfolders.**
  `trt_iso_find_image_in_dir` searches two levels down, prefers a cooked `.iso`, and
  resolves a `.cue` sheet to its `FILE` track; every candidate must open as an image
  (a truncated `.bin` is skipped, not mounted). A folder that ships both a stray
  installer and a disc image now mounts the image when the image's best exe wins.
  Covered by `tests/test_iso.cpp` stage 6.

## Engine walls (open)

- **ARM64 is the current guest-arch wall.** `game-stage.py` stages PE32 (x86-32)
  via the in-tree x86-32 JIT/interpreter (`tools/game_stage`/`src/host/main.cpp`)
  but refuses ARM64. PE32 is still experimental: no 32-bit title has a console
  completion artifact yet. ARM64 would need a separate interpreter/JIT and
  ABI decision (docs/console-type.md and docs/04-support-roadmap.md).
- **Xbox GDK / GameOS packages are not Windows targets.** An x64 Scarlett/GDK
  build (`MicrosoftGame.Config`, `gameos.xvd`, `xgameruntime`/`gamingservices`
  imports) is a console package, not a Win32 desktop game. The LAN dashboard and
  `tools/auto-compat.py` now flag it as unsupported instead of showing a
  misleading D3D11 badge. Tiramisu does not bypass platform or DRM checks.
- **D3D12 execution beyond the triangle gate.** Device/queue/list/PSO/draw/fence/present
  gate passes (`test_d3d12_triangle`); real game draw paths (descriptor tables,
  compute, barriers) and hardware execution remain unverified.
- **Video decode** — unimplemented (Bink stubs added; real decode still missing).
- **VFS case sensitivity** — FIXED: `trt_vfs_resolve_case_insensitive()` walks path components case-insensitively as a fallback when exact path doesn't exist. Fast path (exact match) unchanged for performance.
- **Universal stub fallback** — NEW: unknown DLLs and missing symbols now auto-register as STUB (fail-visible, returns 0) instead of failing the import table. Games boot instead of crashing on missing exports. Calls are logged as STUB for visibility.
- **Real Bink video decode** — stubbed only (returns null). Full decode requires RAD Game Tools SDK (proprietary). Cutscenes unavailable.
- **D3D12 game draw paths** — the triangle/presentation gate passes, but real game draw paths (descriptor tables, compute, barriers) remain untested.
- **ARM64 / non-x86 guest archs** — not feasible today (same wall as game-stage; x86-32 JIT is in the tree and gated).
- **Wwise audio** — the built-in fallback is a stub: init, `RenderAudio`, and bank-load return `AK_Success`, but banks are not parsed and no samples are submitted. A game-shipped native `AkSoundEngine.dll` is preferred by the native-override path; without it, Wwise titles are silent.
- **Crash reporting network POST** — setting toggle + local crash.log writing implemented. Network POST requires maintainer endpoint setup (see docs/crash-reporting-plan.md). Local payload shape is exercised offline via `tools/crash_report_preview.py`.
- **MinGW-compiled games** — low API coverage (e.g. botw-native 41.9%) due to GCC CRT function names not in bridge tables.
- **Performance profiling** — no baseline measurements exist; needs real hardware.
- **Miles audio** — the built-in `mss32.dll`/`miles.dll` fallback returns success but allocates no sample or stream handles, so nothing plays. A game-shipped native Miles DLL is preferred; bank/stream decode in the fallback is unimplemented.
- **Kernel anti-cheat (EasyAntiCheat/BattlEye/Vanguard)** — unsupported by contract. Tiramisu does not bypass anti-cheat or DRM; a title that requires them is Tier X, not a work item.
- **Per-title quirks remain.** `tiramisu.profile.ini` is the supported override channel, but archive formats, launchers, save formats, and engine quirks can still require title-specific work. Generic provisioning removes bridge-registration boilerplate, not the need to validate a title.
