# Tiramisu 0.2.5.0

This release adds Xbox storage workflows, compatibility updates, and
runtime diagnostics. The comparison starts at the previous public release,
`v0.2.4.12`.
The change history and file inventory at the end cover the entire comparison.
[GitHub source comparison](https://github.com/xanstomper/Tiramisu/compare/v0.2.4.12...v0.2.5.0)

## Install and transfer games

- Both packages have version **0.2.5.0**. The standard and experimental
  keyboard/mouse editions retain their respective package identities and
  signing certificates from 0.2.4.12. Use the same edition for an in-place
  update and keep backups of your games and saves.
- The tutorial now covers Dev Mode enrollment, browser and Linux command-line
  installation, the certificate pair for each edition, and game transfers via
  USB, Device Portal, and the LAN dashboard. Xbox Device Portal and the
  Tiramisu LAN dashboard use different URLs.
- Launch Tiramisu once to create `LocalState/TiramisuGames`. In Device Portal,
  open **File Explorer → LocalAppData → the installed Tiramisu package →
  LocalState → TiramisuGames**. The console library scans unpacked folders and
  supported disc images there. The LAN dashboard also lists unpacked folders
  in this location.
- A complete ZIP uploaded to that folder is opened for stable read, extracted
  into staging, checked for a Windows executable, and published under
  `LocalState/games` without overwriting an existing game of the same name.
  Failed ZIPs stay available in the drop folder. A successful import normally
  keeps the original as `.zip.imported`. Keep space for both copies until you
  remove the archived ZIP.
- USB discovery polls in the background. It merges Win32 drive scanning with
  the Windows.Storage broker and the existing optional folder picker. The
  manifest declares the documented `removableStorage` capability and ZIP,
  ISO, IMG, BIN, and CUE associations. The scanner checks known game folders,
  suitable folders directly on the drive, and reachable storage files. It
  tracks stable item IDs and checks readability per file. You can launch
  directly readable folders and images, or use **Transfer → Download to Xbox**
  to copy a supported item. A complete ZIP is the practical route when Xbox
  limits the file types available through the broker.
- The TV library, USB transfer view, and LAN dashboard show source and import
  information. External game entries are protected from the library's
  uninstall action. Device Portal drops and compatible local, package, and
  configured network directories all participate in library refresh.

[Setup and transfer tutorial](../BEGINNER-INSTALL.md)

## Library, settings, Steam, and controls

- LAN folder upload now handles directory pickers, drag-and-drop paths, and
  single-file or batch streaming more consistently. Individual files are
  staged before replacement, with incomplete requests leaving the previously
  installed file intact. Settings POST requests validate top-level JSON fields
  and preserve unrelated values on a partial update. Refresh and uninstall
  checks use path boundaries.
- The Steam tab and shelf share the Steam install readiness check. Incomplete
  installs and missing executables are distinct states. An installed Steam
  launch path is used when available, and older installs can still use normal
  executable discovery. The downloader and launcher carry forward Windows
  depot and launch metadata handling, rescans and direct launch fallbacks,
  transfer feedback, and stale pending-marker handling.
- Persistent global settings, per-title profiles and writable overrides
  control applicable input, display, memory, audio, and runtime options.
  Hardware defaults respect existing user preferences. Unsupported
  requirements appear in logs and launch preflight.
- Pointer ownership and cursor size/appearance were revised, and controller
  prominence is less sensitive to pointer jitter. The guest receives focus,
  capture, and window lifecycle events through the bridge. Input coverage
  expands across GameInput, HID, DirectInput, XInput, and legacy WinMM joystick
  APIs, including `joyGetPos` and capabilities, thresholds, and capture.
  The separate experimental keyboard/mouse package is available for Xbox
  hardware pointer support. Guest support and physical-device results vary
  by title and console. [Mouse and keyboard details](../../XBOX-MOUSE.md)

## Mounting and the compatibility engine

- The selected PE and reachable shipped DLLs feed a bounded launch profile.
  It describes render and audio candidates, startup and delay-load imports,
  payload closure, executable architecture, and host capability checks.
  Preflight reports missing payloads, executable or runtime problems, graphics
  and compositor limits, middleware gaps, and anti-cheat requirements.
- Dependency evidence now includes the requester, candidate path, startup or
  delay-load role, and probe outcome. A candidate may be unreadable, built
  for the wrong architecture, deferred to runtime resolution, or beyond the
  scan budget. The profile counts omitted edges. These fields describe
  discovery. Provider selection and successful initialization are observed
  while the guest runs.
- Mounted ISO9660/Joliet and UDF content follows the guest's image-drive
  paths. A Windows-style request for a bare module can resolve a DLL from
  the image root after the executable-directory search. Root DLLs are
  materialized on demand. Joliet file version suffixes resolve to their
  Windows filenames, and reads and cache materialization receive
  synchronization.
- Qualified DLL loads and handle queries preserve the full mounted or local
  path, including when two modules share a basename. Missing explicit paths
  stay misses. The PE32 loader maps dependencies into the interpreter's
  address space, executes static TLS and attach callbacks where supported,
  preserves filesystem path and handle identity, and corrects FS-relative
  instruction and byte/word operand behavior.
- Shared Windows API coverage expands across file/volume and time queries,
  directory change notifications, threading and TimerQueue callbacks,
  address waits and unwind registration, registry operations, environment
  and module paths, consoles and dialog diagnostics, WinRT, COM, shell
  links, networking, and legacy CRT/WinMM exports. Restored functions use the
  corresponding PE32 calling conventions and surface documented failure
  states where behavior is unavailable.
- Loader and host cleanup now rolls back failed image maps, address space and
  memory charges, guards guest termination and recursive exception reporting,
  and records guest shutdown and launch-worker faults. Crash reporting is
  optional. Corpus tooling distinguishes importing and mapping a file from
  real guest execution.

## Graphics, console profiles, and desktop apps

- Graphics work covers D3D11 swapchain and window ownership, presentation
  state preservation, MSAA render targets and resolves, a fullscreen blit
  for copy-incompatible present sources, render-target and shader-input
  tracing, CoreWindow fullscreen availability, sample coverage, and
  BC2/BC3 color decoding and texture sampling. D3DX shader/blob interfaces,
  legacy D3D and OpenGL paths, and Unity renderer routing also received
  compatibility work.
- CPU GDI raster surfaces, bitmap fonts, paint lifecycle, blits, primitives,
  clipping, shape/path and transform processing, and GDI+ behavior gained
  broader coverage. Tests reach actual guest-rendered raster pixels.
  The console host still needs a GDI compositor for on-screen desktop apps.
- Added or revised hardware profiles for original Xbox One, One S, One X,
  Series S, and Series X. Profiles set feature-level requests, memory
  headroom, render defaults, and the One/One S ESRAM accounting ledger.
  Boot starts transfer observability early and has a D3D11 WARP fallback.
  The older hardware profiles have offline coverage pending on-console
  validation. They operate within the actual UWP memory limit.
  [Xbox One family acceptance matrix](../xbox-one-family.md)

## Audio, middleware, and optional tools

- The audio bridge adds FMOD FADPCM and IMA-ADPCM paths, FSB5 sample decode
  coverage across supported PCM, ADPCM, and MP3 variants, and supported
  Wwise bank and WEM playback with PCM submission to the host mixer.
  It corrects the `stb_vorbis_info` layout mismatch that could corrupt
  decoder calls. FMOD Studio FSB decode on Xbox remains opt-in while device
  audio is verified. WASAPI and audio allocation/format paths have expanded
  regression coverage.
- DirectStorage now includes factory, file, status-array, asynchronous
  queue, buffer access, and Win32 event/D3D12 fence signaling support.
  Unsupported request modes remain explicit. The PE32 ABI table adds
  exact conventions across many Win32 and middleware exports.
- EOS and GOG Galaxy gain offline-safe lifecycle and status bridges.
  Online entitlement and authentication calls report unavailability
  where appropriate. These bridges do not grant access to protected games
  or satisfy anti-cheat requirements. Bink, Media Foundation, Oodle, CRI,
  Miles, WinRT media, and native provider routing also received work.
- The repository includes an optional, separate Win64 Hermes guest with a
  D3D terminal, workspace tool calls, and its PC inference relay. It is
  built through its own tool workflow. [Hermes guest guide](../hermes.md)

## Build, packaging, and verification

- Game library discovery, USB storage, and the dashboard page moved into
  dedicated modules and updated Wine-style fallback and ABI coverage.
  The build generates Mono bridge sources when needed and keeps the Mono
  output and archive paths distinct. Scripts use portable Bash invocation
  where applicable. Packaging reuses matching signing certificates.
- The standard and experimental KBM artifacts were signed, checked against
  their existing certificates, unpacked and checked for valid manifests,
  and verified against the published checksum file. The two packages use
  the same host binary.
- Previous Series S reports cover builds 0.2.4.48 and 0.2.4.52 through
  0.2.4.62. Cuphead reached D3D11 and successful Presents. On 0.2.4.62,
  colored BC3 inputs reached the GPU but game buffers remained black and the
  menu was not reached. Sekiro reached guest entry in 0.2.4.59 before exiting
  ahead of observed D3D11 initialization. RACCOIN and Celeste gameplay
  evidence belongs to earlier tested builds. The God of War record covers
  the forest scene. These records remain attached to their tested versions.
- This release was built and tested offline. A fresh gameplay, physical USB
  hot-plug, and original Xbox One/One S/One X test on 0.2.5.0 remains open.
