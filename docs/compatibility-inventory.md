## How to read the inventory

The numbers preserve the proposal IDs. **Implemented** applies to the named operation only. **Partial** identifies an existing path and an outstanding behavior. **Stub** means the named path returns a placeholder or unsupported result. **Unlocated** means this audit found no implementation of the specified facility in the examined project paths. The linked file is then the nearest existing integration point. **Boundary** identifies a host or project restriction on the specified operation. Test links identify fixtures available for that contract. They do not imply a fresh test run, a Windows reference comparison or an Xbox pass.

Record five independent observations for each compatibility claim.

| Dimension | Evidence to record |
|---|---|
| API coverage | Requested module, symbol or ordinal, architecture and selected provider. Distinguish a lookup, an invoked fallback and a completed operation. |
| Windows behavior | Run the same small program on Windows and Tiramisu. Compare return value, last error when defined, output bytes, ownership, callback ordering and observable side effects. |
| Execution | Identify executable fingerprint and mode, guest entry, worker progress, renderer readiness, first visible game frame, menu response and gameplay separately. |
| Performance | Measure app memory limit and peak, frame-time distribution and measurement interval on the named package and console. Screenshot cadence cannot supply frame timing. |
| Platform feasibility | Record model, OS, package capabilities, host API result and the tested fallback. Keep offline predictions separate from a device observation. |

### Console and guest scope

Series S has named device artifacts. One, One S and One X have console profiles, feature-level selection and offline checks. Series X also has a profile. No separate device pass for those four models was established here. Capture actual app memory concession, negotiated graphics feature level, input backend and suspend/resume on each. The ESRAM ledger on One and One S tracks candidates while the driver controls residency. Installed system RAM is unsuitable as a guest allocation limit. [Family profiles](xbox-one-family.md) · [Hardware validation](console-validation.md)

Native Win32 x64, interpreted PE32 and managed execution have distinct paths and proof requirements. The x86 block recompiler caches decoded operations. Its presence cannot establish permission to emit executable code on a console. Linux-native binaries, ARM guests and Xbox GDK/GameOS packages fall outside the verified PC guest scope. Native child processes and kernel drivers require separate host support. Keep ownership, signing and anti-cheat requirements intact. [PE32 report](pe32-execution-report.md) · [Known issues](known-issues.md)

## First four engineering tasks

1. **Find the first lost color in the shared D3D11 path.** Use a bounded per-frame trace from one real draw to the texture subresource it writes and the buffer Play presents. Record the target descriptor, viewport, sample count, color write mask and readback at each transfer. Build a small regression fixture around the first observed divergence and verify that it fails before the fix. The device gate is a visible Cuphead menu followed by a visible controller response. Exercise the same operation with a second independent workload.
2. **Preserve a reason for pre-render termination.** On the same package, trace Sekiro's startup through worker entry, last completed operation and process exit. Persist the checkpoint so it survives process disappearance. Seek a Windows comparison for the first divergent operation. Implement a shared behavior once the trace identifies one. Reaching device creation is progress. Rendering and gameplay have their own gates.
3. **Make mount and provider selection reproducible.** Build a synthetic two-depot fixture with a nested executable, root DLL, delayed optional renderer and distinct writable save path. Run it through Play and the offline harness. Compare executable, arguments, current directory, content fingerprint and selected providers. Interrupt an update and inject a collision. The previous validated install and save must survive. Request a legitimate owned multi-depot install for hardware confirmation.
4. **Prove breadth on independent paths.** Start with a PE32 D3D9 executable that exercises a callback and can save/reload. Separately run a DX12-only workload through descriptors, synchronization, compute or draw and final pixels. For Java, first prove the JVM/JNI and LWJGL graphics/audio path on an authorized minimal sample. A Project Zomboid or other title receives a result only after its original executable and content pass the same device gates.

Each task should produce the exact build, smallest failing fixture, before/after results and remaining unverified stages. Use the same evidence fields for unrelated engines. Keep game assets, private logs and credentials out of the repository.

## Inventory by proposal ID

A source link identifies the implementation or the nearest integration point inspected. For unlocated facilities, the audit also examined tracked filenames in the runtime, host, tools, tests and vendored tree and searched for entry points such as JNI_CreateJavaVM and MsiInstallProduct. Unnamed forks and untracked private files were outside this search.
